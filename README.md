# just-hide-your-tray-icons

[![build](https://github.com/Heisenberg4441/just-hide-your-tray-icons/actions/workflows/build.yml/badge.svg)](https://github.com/Heisenberg4441/just-hide-your-tray-icons/actions/workflows/build.yml)

Минималистичный аналог Bartender для macOS. Прячет иконки меню-бара за одну
стрелочку — клик по ней возвращает их обратно.

```
до:     ⊖ 🎤 Ⓦ ⛰ 🅐 🔋 ᴄ45° ɢ41°  ‹  ⚙︎  Thu Aug 20 19:45
после:                            ‹  ⚙︎  Thu Aug 20 19:45
```

Нативное приложение на Swift + AppKit. Без зависимостей, без Xcode-проекта, без
запроса каких-либо разрешений — ни Accessibility, ни записи экрана. Весит 300 КБ.

- **Прячет всё лишнее одним кликом** и возвращает вторым.
- **Убирает и системный шеврон `«`**, который macOS 26+ рисует сама, — иначе в
  баре торчали бы две стрелки.
- **Умеет оставлять нужные иконки видимыми** — язык, батарею, что угодно.
- **Автозапуск** через `SMAppService`, **автоскрытие** по таймеру,
  **переключение снаружи** по системному уведомлению (удобно вешать на хоткей).
- **Сама подстраивается** под ширину меню активного приложения и под
  подключение мониторов.

## Быстрая установка

Из исходников — нужны Command Line Tools (`xcode-select --install`), больше
ничего:

```bash
git clone https://github.com/Heisenberg4441/just-hide-your-tray-icons.git
cd just-hide-your-tray-icons
./install.sh
```

Либо готовой сборкой со страницы
[Releases](https://github.com/Heisenberg4441/just-hide-your-tray-icons/releases):
распакуйте `JustHide.zip`, положите `JustHide.app` в `/Applications` и снимите
карантин — приложение подписано ad-hoc, без платного Developer ID, поэтому
Gatekeeper блокирует его после скачивания:

```bash
xattr -dr com.apple.quarantine /Applications/JustHide.app
open /Applications/JustHide.app
```

Сборка из исходников этого шага не требует.

Скрипт соберёт universal-бинарник (arm64 + x86_64), положит `JustHide.app` в
`/Applications` и запустит. Иконки спрячутся сразу.

Дальше — правый клик по стрелочке → **Launch at Login**, чтобы приложение
поднималось само.

Обновиться: `git pull && ./install.sh`. Удалить: выйти через меню и стереть
`/Applications/JustHide.app`.

Если не хочется класть в `/Applications` — `./build.sh` соберёт приложение в
`build/JustHide.app`, запускайте оттуда.

## Как пользоваться

| Действие | Что делает |
|---|---|
| Левый клик по стрелке | Спрятать / показать иконки |
| Правый клик | Меню с настройками |

В меню:

- **Hide Again After 15s** — сам прячет иконки через 15 секунд после показа
  (по умолчанию выключено). Не сработает, пока курсор в меню-баре.
- **Keep One More / Fewer Icon Visible** — выбрать, какие иконки не прятать.
- **Hide macOS Chevron Too** — прятать ли заодно системный шеврон `«`
  (по умолчанию включено).
- **Launch at Login** — автозапуск.
- **Reset Icon Position** — вернуть стрелку на место, если утащили её ⌘-драгом.
- **Quit** — перед выходом возвращает иконки на место.

### Хоткей

Приложение слушает distributed notifications, так что переключать можно снаружи —
из Raycast, Shortcuts, Hammerspoon или чего угодно:

```
com.jhyti.justhide.toggle
com.jhyti.justhide.show
com.jhyti.justhide.hide
```

## Что оставить видимым всегда

Прячется не «всё подряд», а всё, что **левее разделителя**. Разделитель виден
как тонкая палочка `|` рядом со стрелкой, когда иконки показаны.

Чтобы иконка не пряталась, она должна оказаться правее палочки:

1. **Двигать разделитель** — пункты меню **Keep One More / Fewer Icon Visible**,
   каждый сдвигает границу на одну иконку.
2. **Двигать сами иконки** — ⌘-перетащить нужную правее `|`, пока иконки
   показаны. macOS запомнит порядок сама.

Второй способ нужен, когда хочется оставить конкретные иконки (скажем, язык и
батарею), а правее них есть что-то ещё: приложение двигает только собственный
разделитель, а не чужие иконки, поэтому видимой остаётся непрерывная правая
группа, а не произвольный набор. Один раз перетащили — дальше работает само.

## Как это работает

Публичного API «спрячь чужие иконки» в macOS нет и никогда не было — все
подобные приложения (Bartender, Ice, Hidden Bar, Dozer) делают один и тот же
трюк, и здесь он же:

1. Приложение создаёт два своих status item'а — видимую **стрелку** и пустой
   **расширитель** слева от неё.
2. Меню-бар раскладывает иконки справа налево, поэтому раздутый расширитель
   выталкивает всё, что левее, за пределы доступной ширины — и macOS их
   сворачивает.

Позиция задаётся через недокументированный, но стабильный ключ
`NSStatusItem Preferred Position <autosaveName>` в домене самого приложения.
Три неочевидных вещи про него:

- значение — это **ранг справа налево**: меньше = правее;
- **ноль и отрицательные игнорируются** как «без предпочтений», поэтому здесь
  `0.5` и `1.5`, а не `0` и `1`;
- читается он **в момент присвоения `autosaveName`** — записывать нужно строго
  до этого.

Главная сложность — что нельзя просто поставить `length = 10000`. Если item не
влезает, macOS его не «вжимает», а выбрасывает с экрана целиком, и тогда не
скрывается ничего. А свободная ширина всё время разная: меню активного
приложения живёт в той же полоске. Поэтому длина не константа — `calibrate()`
подбирает её по живому меню-бару: растит расширитель шагами по 60pt, пока тот
ещё помещается и пока это ещё что-то даёт, и откатывается назад, если нет.
Сверху длина ограничена 45% ширины самого узкого экрана: примерно на половине
ширины macOS перестаёт раскладывать расширитель и все иконки возвращаются.

Пересчёт происходит при смене активного приложения, при изменении конфигурации
экранов и раз в 5 секунд на всякий случай. Проверка смотрит не только «стоит ли
расширитель на своём месте», но и «делает ли он ещё свою работу»: после того как
бар зажало и приложение отступило, оно само возвращается к работе, когда место
освобождается.

Приоритет при нехватке места — **сохранить стрелку видимой**: без неё иконки уже
не вернуть. Если места нет даже на минимальный расширитель, приложение отступает
и ничего не трогает.

### Про системный шеврон `«`

macOS 26+ сама сворачивает то, что не влезло в бар, и рисует рядом свой шеврон
переполнения. То есть наивная реализация даёт **две стрелки** — системную и
нашу, — причём системная ещё и подтормаживает на анимации.

Убрать её штатно нельзя: на macOS 27 весь меню-бар это одно окно WindowServer,
отдельных окон у иконок больше нет, шеврон рисуется внутри системной отрисовки,
у него нет ни AX-элемента, ни настройки (приватный
`-[NSStatusItem _setOverflowSpecifierPriority:]` на новой сцен-реализации
`NSSceneStatusItem` — заглушка, значение не сохраняется).

Зато его можно **проглотить тем же расширителем**. Замеры на macOS 27:

| длина расширителя | иконки | системный `«` |
|---|---|---|
| до упора | спрятаны | **виден** |
| упор + 40…+250 | спрятаны | **исчез** |
| дальше | **вылезают обратно** | — |

Поэтому калибровка не останавливается на упоре, а перелетает через него на
+120pt — в середину этой полосы — и откатывается назад, если при этом пропала
любая из наших иконок.

### Как выбирается граница видимых иконок

Спросить систему, что ещё есть в меню-баре, нельзя — на macOS 27 чужие иконки
даже не отдельные окна. Поэтому приложение действует наощупь: двоичным поиском
подбирает себе такой «вес» позиции, при котором зазор между разделителем и
стрелкой подрастает ровно на одну иконку. Девять замеров, около двух секунд.

## Ограничения

- **Полоса «перелёта» подобрана замерами, а не задокументирована.** Внутри неё
  всё стабильно, но если Apple поменяет раскладку бара, шеврон может вернуться
  или скрытие перестанет работать — тогда выключите **Hide macOS Chevron Too**.
- **Очень широкое меню у активного приложения** (условный Xcode на узком экране)
  съедает всю полоску — macOS в этом случае прячет иконки сама, без всякого
  приложения. Мы это определяем и не мешаем.
- **Правее Control Center и часов попасть нельзя** — эта зона системная.
- **Конфликт с другими менеджерами меню-бара.** Ice, Thaw, Bartender, Barbee
  борются за тот же самый крайний правый слот. Держите включённым что-то одно.
- Не проверено на маках с «челкой» и на нескольких мониторах: длина одна на все
  экраны, поэтому берётся ширина самого узкого.

## Требования

macOS 13+ (собирается и запускается; вся возня с системным шевроном имеет смысл
только на macOS 26+). Command Line Tools. Xcode не нужен.
